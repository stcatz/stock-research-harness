# 日常入口 v1：本地旁路

仅调用原 `a-share-research` CLI，`--workspace` 放在子命令前。生产调度、发布、通知均未接线。

## 盘前

本次为日常研究，不是开发。读取合同、经验版本、上一业务日 journal 索引与本次已冻结 snapshot。人工核验官方证据和同行覆盖后，使用明确 snapshot ID；不在研究过程中联网补材料或改代码。

请求文件内容：

```json
{"business_date":"2026-09-01","snapshot":{"selector":"id","snapshot_id":"cn-20260901-0008-hithink-ai-discovery-v2"},"top_n":5}
```

入口：`a-share-research --workspace <runtime> premarket --request-json <request.json>`。
日期为信息截止业务日，不是执行日；早于该日 07:00 时拒绝运行。现阶段固定旁路，不能通过参数改为生产。记录真实时钟；历史输入不足仍保留降级状态。

## 收盘

收盘任务不依赖聊天记忆。用盘前返回的 `record_id` 和显式结果快照：

```json
{"forecast_id":"cn-handoff-f-<returned-id>","snapshot":{"selector":"id","snapshot_id":"<actual-close-snapshot-id>"}}
```

入口：`a-share-research --workspace <runtime> close-review --request-json <request.json>`。
只追加，不改原预测。所有原候选（含排除项）保留，缺少同日行情、前收、分钟路径或语义核验时保留 UNKNOWN；结果快照可晚到，但不成为原预测的证据。

## 回读与查找

- `journal-list --request-json <file>`：`{"business_date":"2026-09-01"}`。
- `journal-read --request-json <file>`：`{"record_id":"<returned-id>","max_chars":20000}`。
- `artifact-read --request-json <file>`：`{"artifact_id":"<returned-id>","section":"report","max_chars":20000}`。

读取可能分页，必须检查 `truncated`，并将 `next_offset` 作为下一请求的 `offset`；按原顺序保留空白拼接。完整交接 JSON 在原 SQLite `payload_json`；本机完整报告可用 `artifact-read --complete` 导出。终端预览不是私人送达回执。保存或回读失败必须返回非零退出码，不发布。

## 周复盘

按日期索引比较同一预测 ID 下的结果，区分 fixture、历史重建、未来正式样本。固定条件与基准未定义前，不计算策略胜率。记录流程遗漏、反例与待验证假设，不依据单日行情更新权重。

现有盘前—同日收盘链保持独立。对新版本研究 artifact 的 T+1/T+5/T+20 观察，使用 `feedback-review` 并指定原 `artifact_id` 和结果 `snapshot_ids`，详见 [研究反馈 v1](../../a_share_research/docs/RESEARCH_FEEDBACK.md)。它不替代本合同的正式样本验收，不更新生产调度。

## 2026-09-21 用户追加：每日早报首页固定判断

适用于现有每日07:00人工研究报告及其交接，从下一份晨报起持续执行。用户要求每天直接回答市场阶段、主流板块、核心标的以及各核心正在交易的概念。本节是报告内容要求，沿用既有证据、权限与研究边界，不把人工备忘变成正式ResearchPacket，不回填旧报告或改旧冻结条件。

时间说明后，正文开头必须先给明确结论，再展开既有五层推理与证据附录：

1. **市场处在什么阶段**：回应主跌、主升、高位震荡、低位试错四类；给当前最符合证据的阶段及依据。过渡或混合状态须写准确描述，如“分歧后修复、主线试错”，不能为了四选一硬套。分别解释整体情绪、旧高位接力、重点题材的阶段；“高/低位”说明指价格位置还是情绪周期，缺证据不称价格低位。至少给支持事实、相反证据和具体改判条件，结合可得连续3—5交易日强弱/失败群体反馈。
2. **主流板块有哪些**：按当前市场证据排序，区分持续主流/主攻候选、扩散支线、轮动方向和新挑战者。说明各方向为何排在前面，不能把研究优先级或论坛热度直接当市场主流；列出退出短期重点的方向及相对上一版变化。只有局部样本时明确范围，最多三个优先研究问题。
3. **主流板块的核心标的是哪些**：列公司名、代码和角色，直接回答情绪龙头是否已能确认；区分容量中军候选、弹性核心、业务核心和连板高度参照。用相对表现、连续性、核心与跟随关系解释地位，不只贴标签。每个核心写失去地位的条件，最高板不自动是龙头，无分钟证据不写带动/回封/卡位因果。
4. **这些核心分别在炒什么概念**：对上表核心及当前重要连板高度参照，简明列主要题材、附加题材、市场在交易的预期、真实主营/业务映射、兑现阶段与反证。明确区分传闻、规划、验证、小批、批量订单、交付及收入利润；概念名称与当日上涨原因的推断分开，缺新增触发证据则写UNKNOWN。公司澄清和小收入占比必须呈现；不得把概念延伸说成确定订单或盈利。

推荐用紧凑表格承载“板块及地位｜核心标的及角色｜主要/附加题材｜当前业务兑现｜支持与撤回条件”，先让用户读懂判断，再展开详证。公司和排序每天重新按证据判断，不把今天示例固化成长期名单。实际时点、行情有效日和覆盖缺口明确；非交易日保留这些判断，但说明没有新A股收盘。

交接保留当天以上结论、来源及条件，晚间沿用原名单和期限检验阶段解释、板块排序、核心角色；只对已到期内容记分，未知和未到期分别保留。研究状态仍仅exclude/continue_research/observe，不输出交易指令。

### 2026-09-23 用户纠偏：三问必须在交付中直接可见

- 报告首页和最终交付消息均逐项回答：**1. 市场阶段；2. 主流板块；3. 核心标的及角色**。第4项概念与业务边界继续保留。不能仅在文件内有答案，交付时只给链接或“报告已完成”；心跳的 `message` 也要简明包含前三项结论。
- 阶段先给一句可读结论，再解释整体、旧高位和新方向的差异。例如可描述“整体震荡分歧，结构上旧高位震荡与新方向试错并存”；这只是写法示例，不是固定市场结论。不能只写“方向切换”来回避阶段判断，也不得为了明确而把未证实的主升或价格低位写成事实。
- “主流板块”回答市场地位及证据排序，不能用“前三研究问题”“研究优先方向”代替。证据只覆盖局部样本时，直接列出其中的主流/主攻候选，并说明未确认全市场主线；另列新挑战者、扩散和轮动，不把它们混成已确认主流。
- 核心名单在交付消息中按板块对应，写名称、代码及最重要的角色；统一情绪龙头不能确认时直接说“暂不能确认”，不能把最高板自动填作龙头。
- 交付前人工核对上述三项是否在消息正文中完整可见，而非只检查文档是否存在对应标题。表达补正另存带实际形成时间的新版本/补充页，引用原报告和信息截止；不更新原冻结条件、不追认盘中结果。
