# 研究反馈与市场观察：冻结、口径与单条件对照

v1 基线：`engine_version=cn-feedback-v1.0`，观测口径 `cn-cohort-feedback-v1`。当前版本为 `cn-plan-v3.0`，v2 市场观察及 v3 计划卡见文末；以下 v1 的累计口径继续适用。
范围是 A 股研究，不涉及交易执行。US 继续使用独立引擎、日历、适配器和运行目录。

## 数据先过关

- 正式运行仍只读取冻结快照。采集失败不退回演示数据，不把旧快照标为今日行情。
- `CURRENT_SESSION` 只表示快照日期符合最近已完成的交易日；不表示证据充分、行情字段齐全或候选值得观察。每个候选还必须有自己同一交易日的日线证据，才能通过 `market_freshness`。
- 有带来源的完整交易日历时按其判断；无日历时只承认当日 15:00 后的数据。跨日无法核定则为 `UNKNOWN_CALENDAR`，超过 96 小时则为 `STALE`。96 小时仅为保守过期上限，不是交易日推算规则。未来快照为 `FUTURE_INPUT`。
- 日线历史日期与 HiThink 响应抓取日期不同时，无日期的实时快照无法参与同日校验：记录 `NOT_COMPARABLE`，不获取实时前收价冒充历史前收价。同一日仍严格核对 OHLC、量、额；不一致继续报错。
- 未来线索和缺少可用来源的市场背景会被隐藏。题材阶段仍是研究种子的判断，报告明确标注，未实现自动情绪周期分类。

`run` 摘要的 `status=completed` 只代表程序完成。判断数据是否可用还要看 `data_readiness`、证据门槛及缺口。

## 冻结对象与指标

以当前请求选中的全部候选为样本，包括排除项。股票在多个题材下出现时保留多个研究假设；市场广度和组成员按股票代码去重。这是研究成员覆盖，不是全市场或完整行业覆盖。

| 对象 | v1 固定定义 |
|---|---|
| 观察锚点 | 输入快照对应的已完成日线日期。收盘早于报告生成，只作研究比较，不是可用成交价 |
| 强势组 / 弱势组 | 按当日 `close / provider_reference_preclose - 1` 排序；各取 `min(20, floor(有效数/2))`，不重叠；同值按代码排序；未知成员单列 |
| 题材成员 | 原种子的候选代码表，随输入哈希冻结；后续上涨不会增加新成员 |
| 广度 | 上涨 /（上涨＋下跌），另列平盘、未知、总数；缺少参考前收或有效交易状态时保持未知 |
| 扩散 | 固定题材内相对上证综指的变化：中位数、最低值、正值比例、有效/全部成员数 |
| 成交集中度 | 固定成员的 `Σ(成交额 / 组总成交额)²`；缺失、冲突、总额为零时未知 |
| 前期强弱反馈 | 使用当前快照重建前一交易日分组，再观察当前收盘。标注重建，不能冒充前一天就已登记的名单 |

价格反馈只使用不复权日线中的**供应商参考前收价**，同时要求 `trade_status="1"`。
多日口径是逐交易日 `close / preclose` 连乘，不用跨除权日的原始收盘比。它不是含现金分红再投资的总回报，也不是可实现收益。无法确认参考价或交易状态时不计算。

复盘按官方或结构化市场日历的第 1、5、20 个交易日推进，不能用工作日函数替代。未到期 `PENDING`；到期后缺价、停牌、矛盾报价、缺日历或缺基准覆盖均 `UNKNOWN`。有效成员统计始终同时给出全部成员分母。未来、缺失成员不会被填零或剔除，最低值是横截面最低相对变化，不是盘中最大不利波动。

## 交易日历输入

在研究 seed 的 `evidence` 中提供 `category="trading_calendar"`、`source_level="official"` 的证据，保留六项来源/时间字段；其 `calendar` 为：

```json
{
  "market": "CN",
  "exchanges": ["SH", "SZ"],
  "coverage_start": "2026-01-01",
  "coverage_end": "2026-12-31",
  "complete": true,
  "sessions": ["2026-01-05", "2026-01-06"]
}
```

以上 `sessions` 仅展示格式，**不是完整日历，不可作为生产输入**。生产列表须覆盖声明区间，并保留官方休市安排及标准化计算依据。`complete=true` 是数据提供者的覆盖声明，程序只能检查结构，不能证明列表未漏交易日。临时休市通知、覆盖区间变化需新证据版本；多个日历冲突时停止计算，不按输入顺序选一个。北交所需另行核验并声明覆盖。不得回填本地首次可得时间或把发布日期精度伪装成精确发布时刻。

## 运行和复盘入口

命令前统一指定 `a-share-research --workspace <runtime>`。使用运行返回的真实 ID，以下占位值不直接执行。

先照常 `run --request-json <request.json>` 生成不可变报告和组名单。之后用明确的结果快照追加观察：

```json
{"artifact_id":"<原报告 artifact_id>","snapshot_ids":["<结果快照 ID>"]}
```

入口是 `feedback-review --request-json <review.json>`。可传 1–64 个结果快照，支持逐日追加到达的数据。原始输入从原报告目录验证读取；后续输入不修改原研究结论。输入哈希、原组名单、全部候选及排除项、各期限观测、固定组分布、R0/R1 对照写入现有 SQLite 的 `cn_feedback_records`，不另建数据库。

记录 `formal_sample=false`、`mode=shadow`，测试与真实数据不能混用。保存相同内容时复用原记录；新结果追加新 ID。数据库拒绝 UPDATE/DELETE；回读同时核对原报告、记录及复盘报告。写文件中断后可从数据库恢复缺失文件，已存在但被修改的文件则报错。

- `feedback-list`：`{"artifact_id":"<原报告 ID>"}`，返回至多 100 条记录；若 `truncated=true`，不可声称返回了全部历史。
- `feedback-read`：`{"record_id":"<复盘或预期 ID>","max_chars":12000,"offset":0}`。
- `artifact-read` 和 `journal-read` 也支持 `offset`。每页保留原始空白，按 `next_offset` 连续读取至 `truncated=false`。偏移是 Unicode 字符数，不是字节数。
- 本机 CLI 可用 `artifact-read --complete --request-json <read.json>` 一次导出全部已验证页面；每日 wrapper 已使用此模式。DSH 仍有单页输出上限，需循环读取。

## 预期登记与修改

入口 `hypothesis-register --request-json <hypothesis.json>`：

```json
{
  "artifact_id": "<原报告 ID>",
  "candidate_id": "<原候选 ID>",
  "kind": "price_feedback",
  "expectation": "需要观察的具体预期",
  "horizon_sessions": 1,
  "prior_evidence_refs": ["<原报告内可用证据 ID>"],
  "new_evidence_refs": ["<原报告内可用证据 ID>"],
  "counterexample": "能够解释相反结果的情况",
  "invalidation_condition": "什么可核条件将反对该假设"
}
```

价格假设固定期限为 1、5 或 20 个交易日；可另给未来 `evaluation_at`。无明确评估时间时记录 `UNKNOWN_CALENDAR`，不能凭登记文本自动评定命中。经营假设使用 `kind="business_fact"`，必须给出未来 `evaluation_at`，不能用价格期限替代。催化时间若已过期会显式标记。

预期属于研究员的预期，不是市场共识。缺少前一版本或新增证据则 `expectation_gap=UNKNOWN`；都有证据也只是待人工比较，不能自动声称超预期。语义确认/证伪始终为 UNKNOWN，待独立事实复核，不能用上涨替代。

修改时保留原候选并增加 `supersedes_id` 和 `revision_reason`，保存父记录哈希。登记使用真实系统时间，不倒填研究截止时点；晚登记的假设不能用于原报告的事前预测成绩。

## R0/R1 影子对照

固定实验 `cn-r0-r1-strong-feedback-v1`：R0 是现有研究状态、角色、代码排序。R1 只增加一个条件——题材前一交易日强势组在当前收盘的相对表现，在相同状态与角色内降序排序，平分保持 R0 顺序。两组使用相同 `top_n`、同一冻结候选集和期限。

所有非排除候选的题材都必须有完整前期分组及强势组反馈，才输出 `COMPUTED_NOT_VALIDATED`。否则 `UNKNOWN_NO_REORDER`，R1 等于 R0。正式报告的优先候选始终采用 R0。复盘提供两组覆盖率、中位数、最低值和正值比例，但有效性仍为 UNKNOWN。

这是同一份数据的配对影子比较，不是随机实验。重叠题材、重复股票、相邻日期及行业暴露会产生相关性；单日结果、样本数量阈值或回补数据都不能证明增量效果。没有稳定、独立的时序外证据，不升级排序，不继续为某个结论调参。

## 当前数据限制

HiThink 历史接口没有完整提供逐日参考前收及交易状态；无法靠相邻收盘、正成交量或名人语录补造。此时分组、强弱反馈和排序增量保持 UNKNOWN，后续价格窗口即使成熟也可能无法计算。要提高覆盖率，应显式采集口径合格的来源并保存新快照；不静默换源。

版本内不实现自动情绪阶段判定、盘中承接、真实参与者盈亏、涨停规则跨制度比较或自动语义裁决。

## v2：先区分能观察什么，再解释市场

当前实现 `engine_version=cn-feedback-v2.1`。v1 的日线、日历、累计反馈、R0/R1 门槛继续适用。
新增 `market_diagnostics` 使用 `cn-market-observation-v2`，并不把现价替换为历史日线。

| 能力 | 必需输入 | 输出与范围 |
|---|---|---|
| 当前全市场分布 | 完整分页列表、供应商报告的百分数涨跌幅、正成交量、证据可得时间 | 每只股票的观测与缺失；涨跌分布、分位数、代码组；不认定逐股收盘日期或交易状态 |
| 当前冻结强弱组 | 上述有效横截面 | 各取最多 20 只且不重叠，缺失成员单列；只是观察锚点，不自动进入候选，也未接通全市场组的跨日复盘 |
| 特色池与梯队 | 指定日期的完整涨停、跌停、炸板成员 | 供应商连板标签按代码前缀展示；不是制度校验，也不是盘中状态机 |
| 固定题材表现 | 原种子成员在现价横截面的观测 | 中位数、正值比例、成交额集中度及覆盖；不是全行业扩散或前后变化 |
| 催化重核 | 原始催化日期及截止时间 | 已过期产生逐候选研究任务；全部过期为 NOT_READY，不能写成不知道是否过期 |
| 事实与市场关系 | 候选官方事实门槛、当前涨跌幅 | 正反馈不证明经营因果；负反馈产生待解释问题，不自动证伪或更改研究状态 |

横截面保存在规范化证据的 `cross_section`；完整特色池保存在 `pool_membership`。只存白名单字段及来源索引，不保存原始供应商响应。代码不重复；声明完整时条数必须吻合；未来证据不进入观察；无量或缺失涨跌幅保留未知。观测的百分数单位为 1.25 表示 1.25%，不得混为 0.0125。

“炸板池比例”严格定义为：炸板池去重成员数 /（涨停池与炸板池成员并集数）。池状态完整且分母非零才计算；它不是盘中事件次数，也不保证各供应商的池定义等价。代码前缀只作分组，不据此判定 ST、新股、板块限制或参与者身份。

`READY` 只描述对应能力的输入覆盖，不代表整个研究已有效。历史参考价反馈能力要求所提供候选日线均满足 v1 口径；它本身仍不保证某个期限已到、基准齐全或所有目标交易日都覆盖，具体期限由原复盘模块判断。不能用“现在有涨跌幅”宣布累计复盘已修好。

报告优先展示覆盖、有效窗口、当前分布、梯队、固定成员表现和补证任务，再保留原始研究卡片与证据。原卡片中的阶段、角色和缺口属于旧研究输入，不能自动续期。无新增正式披露时不伪造下一催化日期；三个正式研究状态与 R0 排序不变。

### 判读合约与真实执行边界

新增版本化 `cn-evidence-interpretation-v2` 合约：先说明覆盖和时点，再对照旧研究与新反馈，列支持解释、相反解释、证伪条件及下一条证据。每个数字追溯计算字段和来源 ID。单份横截面不判定情绪转折；缺少事前预期不声称超预期；正成交量不冒充已核交易状态。

DSH 的 `cn_artifact_read` 描述已要求使用该合约；本机确定性引擎不会调用独立语言模型，字段为 `model_execution=NOT_RUN_BY_DETERMINISTIC_ENGINE`。这是一份真实可读的判读约束，不是已经执行过模型研判的声明。

历史复盘报告按存档哈希验证，不再依赖当前版本的展示函数。文件缺失时，只在重新生成的内容与旧哈希完全吻合时恢复，否则要求原版本渲染器；不能用新版格式覆盖旧记录。

### 已核供应商能力与后续补数

- HiThink 现价接口有全市场分页、报告涨跌幅及 `prev_price`，但没有逐股交易日。响应时间不能自动分配成每只股票的历史收盘时间。[现价与历史文档](https://fuyao.aicubes.cn/docs/api-reference/prices/)
- 同一历史日线接口提供有日期的 OHLC、量额及复权选择，当前返回未给逐日参考前收与交易状态。这是 v1 严格反馈缺口，而非整个供应商无行情。
- HiThink 交易日历文档为近一年至当前日期的窗口，不能据此生成未来 T+20；继续使用可审计的官方年度安排。[日历文档](https://fuyao.aicubes.cn/docs/api-reference/calendar/)
- Tushare `daily` 文档明确 `pre_close` 的除权参考含义，量额单位也不同。仅作为待验证补源，不宣称已接入或能直接满足全部状态、基准及权限要求。[日线文档](https://tushare.pro/document/1?doc_id=27)
- Qlib、OpenBB、AKShare 是研究/适配框架的参考；安装它们不会自动解决原始数据授权、历史可得时间或缺失字段。

本版本没有验证任何情绪周期标签或研究排序增量；后续优先补合格历史序列、正式披露更新和事前预期，再做时序外比较。美股继续保持物理隔离，A 股特色池和阈值不移植到美股。

## v3：自动日报中的下一交易日计划卡

`engine_version=cn-plan-v3.0`，计划合约 `cn-observation-plan-v1`。每次正常 `run` 均把 `observation_plan` 写入不可变 packet，并置于完整报告的市场观察之前。无需另一个提示词调用；计划生成不意味着盘中监控已启动。

计划日取研究截止之后、已核日历内的下一个沪深交易日；没有日历或未来覆盖时为 UNKNOWN。北交所等未被日历覆盖的代码组不自动沿用这些日期。09:15、09:35、10:00、13:30、15:10 是本版人工检查约定，不是经过回测优化的信号时点；15:10 若收盘数据未到应记录延迟。

固定一张全市场反馈卡，最多一张供应商新线索验证卡，以及两个不同题材的已有候选比较卡。已有候选必须未被排除、已通过官方与结构化市场及行情新鲜度门槛，且有有效当前报价；按本轮报告涨跌幅排序选取，每题材最多一只。该规则仅分配研究注意力，不是龙头识别或收益排序，不改变正式 R0。同组全部成员及未入选候选仍保留。

每卡包含：明确对象与基线、盘前核验事项、要记录的指标、支持/反方条件、条件满足/失败/数据不足时的研究动作、撤回条件、反例、来源、风险与数据缺口。比较卡以“全部成员有效、严格多数为正、组中位数比首次观察提高、比较对象高于其余成员中位数”为本版本记录条件，同时要求更新正式事实及催化。这些是透明、尚未验证的观察约定，不自动评估触发、不证明收益、不替代原证据门槛。单成员不能判定群体响应。

所有未来结果固定 `PENDING_MANUAL_OBSERVATION`。盘中比较必须使用同一日期、同一组成员和相同价格口径；当前横截面不能冒充上一交易日收盘榜。新线索只生成查证任务，不凭供应商标签自动新增正式候选。旧催化到期时卡片明确要求新披露/具体日期，无法完成则不升级研究状态。

记录时填卡片编号、计划/实际时刻、来源及可得时间、行情日期、有效/全部成员、指标、支持/反对/未知、研究动作和撤回原因。当前没有盘中采集、自动提醒、结果裁决或记录导入入口；填写本地记录表不会自动改变数据库中的研究结论。
